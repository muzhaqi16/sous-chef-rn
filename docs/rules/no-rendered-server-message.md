# `sous-chef/no-rendered-server-message`

A server error's `message`, or other copy the server writes, never reaches the screen.

## Reports

A `message` read (`x.message`, `x?.message`, `const { message } = x`) whose object is typed by the server:

- a type declared in `src/graphql/generated/**` or a `*.generated.ts` file (`DeletionBlocker`, `Notification`, an `Error` implementer, an operation result);
- an Apollo or GraphQL error: `CombinedGraphQLErrors`, `CombinedProtocolErrors`, `ServerError`, `ServerParseError`, `GraphQLError`, `GraphQLFormattedError`, `ErrorLike`.

The same read of a field in [the server-copy table](#server-copy-fields) (`SERVER_COPY_FIELDS` in the source): the field is declared in a generated file and the object's `__typename` is the row's type, so a fragment, an operation result and the schema type all match.

It reports only when the value reaches output: a JSX child, a JSX attribute value (`key` aside), an argument to `toastService.*` / `alertService.*`, or an interpolation value passed to `t(…)`. The read is followed through `?.`, `!`, `||` / `??`, either branch of a `?:`, the right side of `&&`, a template literal, `+`, `String(…)`, `trim()`-style string methods, an object or array literal, and a `const` it is assigned to.

## Use instead

- A refusal or blocker: build the copy from its typed fields (`code`, `field`, an enum such as `DeletionBlocker.type`) through `t(key, { name })`.
- A failed read or write: `localizedErrorMessage(error, fallback)`, or `settleMutation` and its `failure.body`. Resolve it in the feature hook and hand the screen a string.
- A notification: `getNotificationCopy(notification, t)` builds the title and message from `type` and the `payload` names.
- A field with no structured data beside it: a generic sentence for its type or context, never the server's text.

## Why

The client sends no `Accept-Language`, so a server `message` is English in every locale, and its wording is not a contract (`"1 active collaborator(s)"`). `sous-chef/no-error-message-branching` stops code branching on it and `sous-chef/no-untranslated-toast` covers toast arguments by syntax; this rule reads types, so it also sees JSX and a message that passes through a variable.

### Classified and left out

- **Mixed: typed by a person, with server sentinels.** `PantryItemUsage.adjustmentReason` is the reason the adjust and correct-weight forms send, except `"stack merge reconciliation"` (`core/src/services/pantry/PantryStackMergeService.ts`) and `"PANTRY_STACK_PURGED"` (`core/src/services/pantry/PantryItemCRUDService.ts`). `UsageHistoryRow` maps those two to local copy and renders the rest as written.
- **Codes, not copy.** `LoginEvent.failureReason`, `triggerEvent` and `riskFactors` carry enum-like identifiers (`RATE_LIMITED`, `failed_attempt`); `ItemPhoto.perspective`, `Recipe.source`, `ItemImage.source` likewise. Rendering one raw is an enum-formatting problem, not server prose.
- **Identifiers and machine values.** `HomeOwnership.transferredFrom` / `ShoppingListOwnership.transferredFrom` (a user id), `PantryItemChange.oldValue` / `newValue` (ids and JSON), `QuantityDisplay.display` / `fraction` / `mixed` (numerals), `ShareLink.universal`, every `cursor`, `url`, token and id.
- **Catalog reference data.** `Item.description`, `Category.description`, `Brand.description`, `HealthBenefit.benefit` / `description` / `scientificEvidence`, `ItemUnit.displayNameSingular` / `displayNamePlural`, `SourceAllergens.contains` / `mayContain`: imported product data, English like the item names beside it, and outside this rule.
- **User content.** Names, notes, `tips`, `description` on `Home`, `Pantry`, `ShoppingList`, `Recipe`, `MealPlan`, `MealTemplate` and `StorageLocation`, `HomeInvite.message`, `RecipeReview.comment`, `ItemEditSuggestion.note`, `MyModerationStatus.appealNotes`.

## Exempt

- react-hook-form's `fieldState.error?.message` / `formState.errors.x?.message`: typed `FieldError` from react-hook-form, carrying the form's own yup copy.
- An `Error` the app built itself, and any value typed `Error` or `unknown`. A hook that widens Apollo's `ErrorLike` to `Error` in its return type hides the source from this rule, so resolve the copy inside the hook.
- A server-copy field copied into an app-declared type (`{ title: n.title }` returned from a projection) is no longer seen. Build the copy where the generated type is still in hand.
- Logging and reporting: a read that reaches no output.
- Test files and `.graphql` documents.
- Files without type information.
